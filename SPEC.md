# ghost — спецификация

Оверлей-суфлёр, невидимый для захвата экрана. Четыре входа в одну историю диалога: **системный звук** (речь собеседника), **микрофон** (уточнения), **текст редактора** (точная копия из браузера) и **экран** (снимок области). Ответ появляется до того, как собеседник договорил.

Версия спеки: 4. Дата: 2026-09-03. Кода нет.

---

## 1. Что определяет весь дизайн

Пять требований задают архитектуру; каждое решение ниже проверяется на соответствие им.

**Т1. Ответ должен быть на экране раньше, чем собеседник закончил фразу.** Не «быстро», а именно раньше. Отсюда: захват непрерывный, распознавание потоковое, запрос к модели **спекулятивный** — уходит по недоговорённой фразе и уточняется по мере поступления слов.

**Т2. Латентность измеряется, а не предполагается.** Приложение инструментирует каждый переход конвейера и показывает реальные тайминги.

**Т3. Промпт — не заглушка.** Модель выдаёт реплику, которую можно **произнести вслух**, а не абзац из справочника.

**Т4. Все входы попадают в одну историю.** Когда собеседник голосом спрашивает «а какая тут сложность?», модель уже видит текст редактора. Один `Conversation`, четыре канала.

**Т5. Отладка идёт целиком офлайн.** На этапе разработки — локальный whisper и локальная модель через LM Studio, ни одного внешнего запроса. Отсюда следствие, которое нельзя отложить: и STT, и LLM с самого начала живут за трейтами с двумя реализациями каждый. Это не «потом отрефакторим», а условие работоспособности.

## 2. Сценарии

### 2.1 Разговор

Идёт созвон. Приложение слушает системный вывод звука.

1. Собеседник начинает говорить. Аудио с loopback непрерывно идёт в кольцевой буфер; VAD размечает речь и паузы.
2. Пользователь зажимает клавишу — «этот вопрос мне нужен». Потоковый ASR выдаёт растущий транскрипт.
3. Как только накопилось достаточно смысла, уходит **первый спекулятивный запрос** по незавершённой фразе. Через ~1.5 с на экране черновик — собеседник ещё говорит.
4. Черновик пересчитывается по мере поступления слов (максимум 3 раза), каждый следующий запрос отменяет предыдущий.
5. Пользователь отпускает клавишу → финальный запрос по полной расшифровке. Финал **заменяет черновик на месте**: совпадающий префикс не перерисовывается.
6. Отдельная клавиша с микрофона: уточнение к последнему ответу («дай цифры», «короче»).

### 2.2 Live coding — правка кода в браузерном редакторе

На экране браузер с редактором, в нём код, который надо поправить.

1. `Ctrl+Alt+1` → приложение вытаскивает **полный текст редактора** через CDP — не картинку — и кладёт в контекст с номерами строк.
2. **Разбор запускается сразу, не дожидаясь вопроса:** модель называет, что не так и с какой строки начинать.
3. Пользователь правит. Повторное нажатие — новый снимок текста; при `send_diff` уходит только изменение.
4. Интервьюер спрашивает голосом → PTT → ответ строится с учётом и вопроса, и актуального текста в редакторе.
5. Вывод тестов или красное подчёркивание — `Ctrl+Alt+2` картинкой: там смысл в визуальном, а не в тексте.

Оверлей всё это время виден пользователю, не попадает в захват экрана и ни разу не забирает фокус.

## 3. Границы

**Делает:** непрерывный захват системного звука, VAD, потоковое распознавание, извлечение текста из браузерного редактора, снимки областей экрана, спекулятивные и упреждающие запросы к модели, потоковый вывод в окно, исключённое из захвата; глобальные хоткеи поверх любого приложения.

**Не делает:** не скрывается от списка процессов, не маскируется под системные компоненты, не противодействует средствам мониторинга — это гонка вооружений, а не инженерия. Не печатает и не кликает за пользователя, не правит код в редакторе сам. Не работает вне Windows в v1.

**Честные ограничения невидимости.** `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` исключает окно из кадра, который DWM отдаёт потребителям захвата. Не защищает от камеры телефона, аппаратного HDMI-сплиттера или карты захвата, зеркалирования на второй физический дисплей. Окно остаётся обычным окном ОС: видно в `EnumWindows`, процесс — в диспетчере задач. `WS_EX_TOOLWINDOW` убирает его из Alt-Tab, панели задач и списка «поделиться окном» — стандартное поведение любого OSD-оверлея.

## 4. Целевая платформа

| Параметр | Значение |
|---|---|
| ОС | Windows 10 build 19041 (2004) или новее — раньше `WDA_EXCLUDEFROMCAPTURE` не существует |
| Деградация на старых ОС | `WDA_MONITOR`: окно в захвате чёрное, а не невидимое. Определять и явно сообщать в UI |
| GPU | **RTX 3080**. `whisper-rs` с фичей `cuda`; локальная модель в LM Studio делит с ним ту же VRAM — бюджет в §10.1 |
| Права | Тот же уровень привилегий, что у приложения в фокусе. LL-хук из непривилегированного процесса не видит клавиши, адресованные окну от администратора |
| Мониторов | Один. Области захвата (§8) делят единственный экран |
| Браузер | Chrome/Edge, запущенный с `--remote-debugging-port` и отдельным `--user-data-dir` (§8.2) |
| Сборка | Нативно на Windows. Репозиторий перенести на Windows-сторону (`C:\Users\user\ghost`), редактировать из WSL через `/mnt/c/...`. Причина: `whisper-rs` тянет C++-сборку whisper.cpp с CUDA, кросс-компиляция из WSL под MSVC — лишняя боль |

## 5. Архитектура

```
┌─ WASAPI loopback (системный вывод) ─┐   ┌─ микрофон (cpal) ─┐
│ непрерывно, 48к стерео f32          │   │ по клавише        │
└──────────────┬──────────────────────┘   └────────┬──────────┘
               │ ringbuf (lock-free, 30 с)         │
               ▼                                    ▼
┌─ поток: аудио-препроцессор ─────────┐
│ ресемпл 48к→16к моно (rubato)       │──── SpeechStart / SpeechEnd
│ VAD по кадрам 30 мс (earshot)       │
└──────────────┬──────────────────────┘
               ▼
┌─ поток: ASR (актор) ────────────────┐  ┌─ поток: текст и экран ───────┐
│ local:  whisper.cpp + LocalAgreement│  │ каскад CDP → UIA → скриншот  │
│ cloud:  WebSocket, interim results  │  │ номера строк / diff / PNG    │
└──────────────┬──────────────────────┘  └────────┬─────────────────────┘
               │ Partial/Commit/Utterance         │ Editor{text} | Screen{png}
               ▼                                   ▼
┌─ поток: core (tokio) ───────────────┐      ┌─ поток: хук клавиатуры ─┐
│ единая история четырёх каналов      │◀─────│ WH_KEYBOARD_LL + pump   │
│ политика спекуляций, отмена in-flight│     │ колбэк: только try_send │
│ стриминг от модели, префиксный кэш  │      └─────────────────────────┘
└──────────────┬──────────────────────┘
               │ UiEvent (mpsc) + ctx.request_repaint()
               ▼
┌─ главный поток: UI (eframe/egui) ───────────────────────────────┐
│ рендер, замена черновика на финал через диф                     │
│ HWND: display affinity + ex-styles + watchdog                   │
└─────────────────────────────────────────────────────────────────┘
```

Ни один блокирующий шаг не выполняется в UI-потоке и ни один — в аудио-колбэке.

| Канал | Тип | Причина |
|---|---|---|
| WASAPI → препроцессор | `ringbuf::HeapRb<f32>` | Аудио-колбэк реального времени: без аллокаций и мьютексов |
| хук → core | `crossbeam_channel`, bounded 64, `try_send` | Колбэк LL-хука обязан вернуться быстрее `LowLevelHooksTimeout` (300 мс), иначе Windows молча снимет хук |
| ASR → core, текст/экран → core | `tokio::sync::mpsc` | |
| core → UI | `tokio::sync::mpsc<UiEvent>` + `request_repaint()` | UI не опрашивает состояние, а просыпается по событию |

## 6. Аудио

### 6.1 Основной канал — системный звук

`cpal` **не подходит**: в 0.18 нет loopback-фичи (проверено: asio/jack/pipewire/pulseaudio и т.п.). Берём `wasapi` 0.24 — WASAPI loopback на устройстве **вывода**.

- Режим shared, event-driven, `AUDCLNT_STREAMFLAGS_LOOPBACK` на рендер-устройстве по умолчанию.
- Формат обычно 48000 Гц, 2 канала, f32 → моно (среднее каналов) → ресемпл до **16000 Гц f32** (`rubato`, `SincFixedIn`, `Quality::Medium`).
- **Тишина.** В loopback-режиме при полном отсутствии звука WASAPI может не отдавать пакеты. Обрабатывать `AUDCLNT_S_BUFFER_EMPTY` и подмешивать нули, иначе временна́я шкала поедет.
- **Смена устройства вывода** посреди разговора убивает поток. Ловить `IMMNotificationClient::OnDefaultDeviceChanged` и переподключаться прозрачно, сообщив в статус-строку.
- Кольцевой буфер **30 секунд** даёт ключевое свойство: клавишу можно нажать **после** того, как собеседник договорил, — фраза уже в буфере.

### 6.2 Второй канал — микрофон

`cpal` 0.18 (WASAPI), устройство ввода по умолчанию. Две роли:

1. **Уточнения к модели.** Отдельная клавиша: пользователь тихо произносит «дай цифры» / «короче» — это идёт не собеседнику, а как правка последнего ответа.
2. **Контекст истории (опция `audio.capture_self`).** Реплики самого пользователя тоже распознаются и кладутся в историю. Модель перестаёт предлагать уже сказанное. Крупный рычаг качества, но удваивает расход на ASR. По умолчанию выключено.

### 6.3 VAD

`earshot` 1.2.2 — чистый Rust, без ONNX-рантайма и файла модели, кадры 10/20/30 мс на 16 кГц.

- **Эндпоинтинг:** конец реплики = тишина ≥ `endpoint_ms` (700 мс).
- **Микропаузы:** тишина 200–400 мс внутри речи — хороший момент для спекулятивного запроса.
- **Гейт для whisper:** не гонять инференс по тишине. Локальный whisper галлюцинирует на тишине; VAD-гейт плюс `no_speech_thold` это снимают.

Запасной вариант при ложных срабатываниях в шуме: `voice_activity_detector` 0.2.1 (Silero через ONNX Runtime) — точнее, но тянет `onnxruntime.dll` в поставку.

## 7. Потоковое распознавание

```rust
enum AsrEvent {
    Partial   { text: String },               // может измениться
    Commit    { text: String },               // стабильный префикс, больше не изменится
    Utterance { text: String, end: Instant }, // реплика завершена
}

trait StreamingAsr: Send {
    fn spawn(cfg: &SttConfig, pcm: mpsc::Receiver<Vec<f32>>) -> mpsc::Receiver<AsrEvent>;
    fn flush(&self);   // форсировать финализацию (отпущена клавиша)
}
```

Различие `Partial` и `Commit` — основа политики спекуляций: запрос строится только на `Commit`-префиксе, иначе черновик будет прыгать вслед за переигранными словами.

### 7.1 Локальный бэкенд — whisper.cpp + LocalAgreement-2

whisper не потоковый по природе. Стандартный обход — скользящее окно:

1. Буфер держит аудио с последней точки коммита.
2. Каждые `step_ms` (600 мс) прогоняем whisper по всему буферу.
3. **Наибольший общий префикс двух подряд идущих гипотез считается стабильным** и уходит как `Commit`. Остаток — `Partial`.
4. Аудио до конца закоммиченного текста отрезается по таймштампам токенов (`token_timestamps = true`), когда буфер превышает `max_window_s` (20 с).

Параметры: `ggml-large-v3-turbo-q5_0` (~570 МБ), `language = "ru"`, `no_context = true`, `suppress_blank = true`, фича `cuda`.

Ожидание на RTX 3080: прогон окна 10 с ≈ 100–250 мс, шаг 600 мс держится с запасом. Но **стабильный текст отстаёт от речи на 1–2 секунды** — цена LocalAgreement-2: слово коммитится только после подтверждения на следующем прогоне.

### 7.2 Облачный бэкенд (прод, M5)

`tokio-tungstenite` 0.30, потоковый WebSocket. Отставание частичных результатов — сотни миллисекунд против 1–2 секунд у локального.

Кандидаты: Deepgram, Speechmatics Realtime, OpenAI Realtime (транскрипция), Yandex SpeechKit (русский как основной + RU-хостинг, минимальный сетевой RTT).

**Протокол выбора (M5, обязателен — иначе выбор будет вкусовым):** 20 записей реального разговора по ≥ 30 с. Метрики: WER на русском; задержка partial; задержка final после конца речи; качество эндпоинтинга; цена за час; поведение при обрыве сети.

## 8. Канал текста и экрана

### 8.1 Почему текст, а не картинка

Задача live coding — не «прочитать изображение», а получить **точную копию кода со всеми символами и отступами**, потому что его надо править и ссылаться на строки. Скриншот для этого негоден по трём причинам:

1. Он содержит только видимую часть вьюпорта.
2. **Monaco и CodeMirror 6 виртуализируют рендер** — непроскролленных строк физически нет ни в DOM, ни на экране. Никакое зрение и никакой OCR их не достанут.
3. OCR вдобавок путает `l`/`1`/`I`, `O`/`0`, ломает `{}` и обратные кавычки, теряет отступы — а в Python отступ есть синтаксис.

Поэтому: **текст берём текстом**, а картинку — только там, где текста нет (вывод тестов, подчёркивание ошибки, диаграмма в условии).

### 8.2 Путь A — CDP (основной)

`chromiumoxide` 0.9.1 → WebSocket к Chrome DevTools Protocol, `Runtime.evaluate` с каскадом по убыванию надёжности:

```js
window.monaco?.editor.getModels()[0]?.getValue()           // Monaco: VS Code, CoderPad, CodeSignal
?? window.view?.state?.doc?.toString()                      // CodeMirror 6
?? window.editor?.getValue()                                // Ace, CodeMirror 5
?? document.querySelector('textarea')?.value                // простой textarea
?? document.querySelector('[contenteditable]')?.innerText   // contenteditable
```

Это даёт **полную модель редактора**, а не отрендеренные строки — главное преимущество над всеми остальными путями.

Условие запуска: Chrome стартует с `--remote-debugging-port=9222` **и отдельным `--user-data-dir`** — в свежих версиях отладочный порт на профиле по умолчанию заблокирован из соображений безопасности. Точную версию, с которой это началось, проверить на M4; практически — просто всегда указывать отдельный профиль. Разовая настройка ярлыка, целиком под контролем пользователя.

CDP даёт бесплатно ещё три вещи: позицию курсора (какую строку правят прямо сейчас), текст условия задачи из соседней панели через `DOM.getDocument`, и `Page.captureScreenshot` — снимок без отдельного скриншотера.

### 8.3 Путь B — UI Automation (без настройки браузера)

`uiautomation` 0.25.0 → дерево доступности Chrome/Edge, `ValuePattern` / `TextPattern` на элементе редактора. Работает без флагов запуска и без расширений.

Ограничение принципиальное и то же самое: **виртуализация**. В дереве доступности лежат только отрендеренные строки. UIA даёт точные символы видимой части — лучше скриншота, хуже CDP.

Применение: браузер запущен без отладочного порта, а код помещается во вьюпорт.

### 8.4 Путь C — скриншот в модель со зрением

Для всего, что не выражается текстом: вывод тестов, красное подчёркивание, диаграмма, вкладка с результатами прогона. И как универсальный запасной путь, если A и B ничего не дали.

`xcap` 0.9.8 — захват монитора, окна или области. Подготовка: длинная сторона до **1568 px** (`fast_image_resize` 6.1, SIMD), **PNG а не JPEG** (артефакты сжатия портят мелкий текст), base64. ~1840 токенов ≈ $0.009 на Anthropic.

**Наш оверлей не попадает в собственный снимок** — бесплатное следствие `WDA_EXCLUDEFROMCAPTURE`. Проверить явно на M0, иначе рискуем отправлять модели её же предыдущий ответ.

Для локального бэкенда этот путь требует VLM (§10.1).

### 8.5 Выбор пути

Каскад при нажатии клавиши: **CDP → UIA → скриншот**, побеждает первый непустой результат. В статус-строке видно, какой сработал: `cdp` / `uia` / `img`. Если вместо `cdp` внезапно `img` — пользователь должен это видеть, а не гадать, почему подсказки поплыли.

### 8.6 Что уходит в модель

Текст редактора — блоком с **номерами строк**: без них модель не скажет «строка 14», а пользователю надо быстро найти место глазами.

```
<редактор файл="solution.py" строк="47">
  1| def merge(a, b):
  2|     res = []
...
</редактор>
```

**`cache_control` на текст редактора не ставится.** Он меняется на каждом захвате, и попытка кэшировать создавала бы новую запись впустую. Кэшируется только стабильное: системный промпт и условие задачи.

### 8.7 Diff вместо полного текста

Оптимизация: при повторном захвате отправлять не весь файл, а diff к предыдущему (`similar` уже в зависимостях). Экономит токены и — что важнее — прямо показывает модели, что изменилось с прошлого раза. Флаг `text.send_diff`; включить после M4 и замерить, не сбивает ли это модель с толку на длинных правках.

### 8.8 Единая история

```rust
enum Input {
    Interlocutor(String),                     // loopback ASR — речь собеседника
    Own(String),                              // микрофон — уточнение или своя реплика
    Editor { file: String, text: String },    // текст редактора (CDP/UIA)
    Screen { slot: String, png: Vec<u8> },    // снимок области
}
```

Все четыре складываются в один `Conversation`. Это и есть смысл Т4: когда интервьюер голосом спрашивает «а какая тут сложность?», модель уже видит код.

## 9. Спекулятивный ответ

Ядро требования Т1.

### 9.1 Политика запуска

Спекулятивный запрос уходит, когда выполнены **все** условия:

| Условие | По умолчанию | Зачем |
|---|---|---|
| Закоммиченный текст вырос на N слов | 10 | Иначе запросы польются на каждое слово |
| С прошлого запроса прошло не меньше | 1200 мс | Защита от шквала при быстрой речи |
| Всего в реплике не меньше | 6 слов | На «Ну, э-э, слушайте» отвечать нечего |
| Спекуляций в реплике не больше | 3 | Потолок расхода |

Дополнительный триггер вне счётчика: **микропауза 200–400 мс по VAD** — говорящий закончил смысловую единицу.

Тот же принцип для текста и экрана: захват сразу запускает **упреждающий разбор**, не дожидаясь вопроса (`screen.auto_analyze`, `text.auto_analyze`).

### 9.2 Отмена

Новый спекулятивный запрос отменяет предыдущий: future дропается, соединение рвётся. Уже полученные дельты отменённого запроса **остаются на экране** до первой дельты нового — иначе панель мигает пустотой.

### 9.3 Финализация

По отпусканию клавиши (`ptt`) или по эндпоинтингу VAD (`auto`).

1. ASR получает `flush()`, отдаёт полный текст реплики.
2. Если финальный текст совпал с префиксом последнего черновика **и** черновик достроился — он повышается до финала, запрос не отправляется. Экономия целого round-trip.
3. Иначе — финальный запрос по полной расшифровке.

**Обычный перезапрос, а не «уточни черновик».** Вариант «вот твой черновик, вот полный вопрос, исправь» экономит мало, а модель цепляется за неверную догадку. Остаётся за флагом `llm.refine_mode` для замера на M3.

Выигрыш даёт не хитрость запроса, а **префиксный кэш**: системный промпт, история и условие задачи у финального запроса те же и уже прогреты.

### 9.4 Замена черновика в UI

- Пока идёт спекуляция, текст приглушён и помечен маркером `~`.
- При приходе финала считаем диф (`similar` 3.2). Совпадающий префикс **не перерисовывается**, меняется только хвост.
- Совпал целиком — просто снимаем приглушение, без анимации.
- Панель никогда не схлопывается в пустоту между черновиком и финалом.

### 9.5 Стоимость (только для прод-бэкенда)

По Opus 5 ($5 / $25 за MTok, чтение кэша $0.50 за MTok). Голосовой запрос ≈ $0.007, с токенами мышления ≈ $0.014. Три спекуляции плюс финал ≈ **$0.06 на реплику**; разговор с 30 вопросами ≈ **$1.5–2 в час**. Снимок экрана: +$0.009 на первый ход, дальше из кэша. Текст редактора не кэшируется (§8.6) и стоит полную цену входа каждый раз — при файле на 300 строк это ~$0.02 за захват, что делает `send_diff` (§8.7) заметной экономией.

Локальный бэкенд бесплатен — это и есть причина, по которой вся отладка идёт на нём.

В статус-строке — накопленная стоимость сессии. `llm.session_budget_usd` останавливает спекуляции (но не финальные ответы) при превышении.

## 10. Бэкенды модели

Две реализации за одним трейтом. Разница в протоколе не должна протекать в `core`.

```rust
enum AssistantEvent { Delta(String), Done { usage: Usage }, Error(String) }

trait Assistant: Send + Sync {
    fn stream(&self, conv: &Conversation, hint: RequestKind)
        -> BoxStream<'static, AssistantEvent>;
}
```

### 10.1 Локальный — LM Studio (разработка, по умолчанию)

OpenAI-совместимый сервер: `POST http://localhost:1234/v1/chat/completions`, `stream: true`, SSE.

| | Anthropic | OpenAI-совместимый (LM Studio) |
|---|---|---|
| Системный промпт | top-level `system` | первое сообщение с `role: "system"` |
| Изображение | блок `image`, `source.type = "base64"` | `image_url` с `data:image/png;base64,...` |
| SSE-дельта | `content_block_delta` / `text_delta` | `choices[0].delta.content` |
| Завершение | событие `message_stop` | `data: [DONE]` |
| `effort`, `thinking`, `fallbacks`, `cache_control` | есть | **не отправлять** |

**Кэширование.** `cache_control` у LM Studio нет, но llama.cpp сам переиспользует KV-кэш при совпадении префикса. Правило то же, что и для Anthropic: **стабильное вперёд, изменчивое в конец**. Архитектура запроса от бэкенда не зависит — это и делает подмену бэкенда бесплатной.

**Бюджет VRAM на RTX 3080.** whisper `large-v3-turbo` q5 с CUDA ≈ 1 ГБ; VLM 7B в Q4 ≈ 5–6 ГБ. На 10-гигабайтной 3080 помещается, но впритык, и браузер тоже берёт своё. Замерить на M2; при OOM первый шаг — whisper `medium` вместо `turbo`, второй — модель поменьше.

**Зрение.** Путь C (§8.4) требует, чтобы локальная модель была VLM (Qwen2.5-VL, InternVL и подобные). Текстовые пути A и B работают с любой моделью — то есть основной сценарий live coding отлаживается и на обычной текстовой модели.

### 10.2 Anthropic (прод, M5)

Официального Rust SDK нет → raw HTTP: `reqwest` 0.13 (rustls) + `eventsource-stream` 0.2. `POST https://api.anthropic.com/v1/messages`, заголовки `x-api-key`, `anthropic-version: 2023-06-01`. Модель по умолчанию — **`claude-opus-5`**.

| Решение | Обоснование |
|---|---|
| `stream: true` | Первые слова на экране как можно раньше |
| `output_config.effort: "low"` | На Opus 5 мышление включено по умолчанию (adaptive) и добавляет задержку до первого токена. `low` её заметно срезает. Явно отключать мышление **не рекомендуется**: задокументированный побочный эффект — утечка `<thinking>`-тегов в ответ |
| `max_tokens: 700` | Реплика короткая; длину дополнительно держит промпт |
| `cache_control` на промпте и на условии задачи, но **не** на тексте редактора | §8.6. Проверять по `usage.cache_read_input_tokens`; при стабильном нуле разбираться, а не мириться |
| Изображение **перед** текстом в блоке | Рекомендованный порядок; заодно держит стабильный префикс первым |
| `fallbacks: "default"` + beta `server-side-fallback-2026-07-01` | Ответ с HTTP 200 может нести `stop_reason: "refusal"`. Проверять `stop_reason` **до** чтения `content` |
| Маркер `status="partial"` в теле сообщения, а не в системном промпте | Признак незавершённости меняется от запроса к запросу; в промпте он ломал бы префиксный кэш на каждом ходе |

**Fast mode** — рычаг, если TTFT не укладывается: до 2.5× выше скорость выдачи на Opus 5, требует одновременно beta-эндпоинта, `anthropic-beta: fast-mode-2026-02-01` и `"speed": "fast"` в теле; тариф $10 / $50 за MTok. Флаг `llm.fast`, по умолчанию выключен.

Повторы: 429 и 5xx — до 2 попыток с экспоненциальной задержкой и уважением к `retry-after`; 4xx — без повторов. **Спекулятивные запросы не повторяются никогда** — к моменту повтора они неактуальны. Пул `reqwest` переиспользуется между ходами: экономит TLS-хендшейк ≈100–200 мс, а при четырёх запросах на реплику это заметно.

### 10.3 Ловушка при замерах

Локальная 7B на 3080 даёт TTFT **200–400 мс** — быстрее, чем Anthropic. Метрики §14, снятые на LM Studio, характеризуют конвейер, но не прод. Вывод «укладываемся в 4 секунды» на локальном бэкенде **ничего не доказывает** и должен быть перепроверен на M5. Это записано в критерий готовности обоих этапов.

### 10.4 История разговора

```rust
struct Conversation {
    system:  String,          // из файла профиля, hot-reload
    turns:   Vec<Turn>,       // Input + выданные ответы
    pinned:  Vec<Attachment>, // закреплённое: условие задачи
}
```

Сброс по хоткею очищает `turns`, оставляя `system`; закреплённое — отдельной комбинацией. `context.max_turns` (20) отбрасывает старые ходы парами — про латентность и цену, а не про переполнение. `context.idle_reset_secs` — автосброс по бездействию, по умолчанию выключен.

## 11. Системные промпты

Промпты живут в `prompts/<профиль>.md`, отслеживаются через `notify` — правка применяется со следующего хода без перезапуска. Профиль переключается `Ctrl+Alt+P`.

### 11.1 `prompts/default.md` — разговор

```
# Роль

Ты — суфлёр. Пользователь ведёт живой разговор. Ты получаешь расшифровку речи
ЕГО СОБЕСЕДНИКА и выдаёшь то, что пользователь может сказать в ответ.

Пользователь читает тебя боковым зрением, за доли секунды, продолжая держать
зрительный контакт. Всё, что не помещается в один взгляд, бесполезно.

# Вход

Вход — результат автоматического распознавания речи. Отсюда три следствия.

1. В нём есть ошибки: перепутанные термины, имена, цифры. Восстанавливай смысл
   по контексту разговора. Не пиши «вероятно, вы имели в виду».

2. Реплика может быть ОБОРВАНА НА ПОЛУСЛОВЕ — тебя вызывают ещё до того, как
   собеседник договорил; такая реплика помечена status="partial". Это штатный
   режим. Отвечай на самое вероятное завершение фразы. Никогда не пиши, что
   фраза неполная, и не проси её договорить.

3. Собеседник может вообще не задавать вопрос. Если это утверждение, возражение
   или рассказ — дай не «ответ», а реплику, которая двигает разговор дальше:
   уточнение, контраргумент, согласие с конкретикой.

Иногда тебе передают текст с экрана пользователя или снимок. Всё, что там видно,
он видит сам — не пересказывай, а используй.

# Формат

Ровно эта структура. Без заголовков, без вступлений, без markdown кроме трёх
маркеров.

▸ Одна фраза, которую пользователь произнесёт вслух дословно. Живая устная
  речь, а не письменная. 10–20 слов.
· Опора: конкретика, на которую он обопрётся, если разговор пойдёт вглубь —
  цифра, название, термин, механизм. 3–7 слов. Максимум три пункта, часто
  хватает одного.
? Только если реплика допускает два прочтения, ведущих к разным ответам:
  один уточняющий вопрос, который пользователь задаст собеседнику. В остальных
  случаях этой строки нет вовсе.

Запрещено: «Конечно», «Отличный вопрос», пересказ вопроса, объяснение того, что
ты делаешь, извинения.

# Достоверность

Пользователь произнесёт твои слова вслух, и ошибка обойдётся ему дорого.

- Цифру, дату, имя, цитату пиши только если уверен. Иначе — формулировка без
  них: «порядка десятков процентов», «в начале двухтысячных».
- Если не знаешь — это и есть лучшая реплика. «Точных цифр по памяти не назову,
  пришлю после звонка» — нормальный ответ. Выдуманная цифра — нет.
- Никогда не подавай догадку как факт.

# Контекст

Тебе передаётся история разговора: реплики собеседника и то, что ты уже
предлагал. Не повторяйся. Если собеседник возвращается к прежней теме — помни,
чем она закончилась.
```

### 11.2 `prompts/livecoding.md` — правка кода в редакторе

```
# Роль

Пользователь правит код в редакторе на глазах у интервьюера и не может
остановиться, чтобы читать. Ты видишь текст редактора и слышишь интервьюера.

# Вход

Текст редактора приходит блоком <редактор> с номерами строк. Это точная копия,
а не изображение. Ссылайся на строки по номерам: пользователь ищет место

Если пришёл diff — это то, что изменилось с прошлого раза.

Снимок картинкой присылают только для того, что не выражается текстом: вывод
тестов, подчёркивание ошибки, диаграмма в условии.

# Формат

▸ Что исправить прямо сейчас, с номером строки. Императив, 5–15 слов.
· Опора: почему это ломается — граничный случай, тип, сложность. До трёх
  пунктов.
⌘ Исправленный фрагмент, до 8 строк. Только изменённая часть, не файл целиком.
? Уточняющий вопрос интервьюеру — только если задача правда неоднозначна.

# Приоритеты

1. Сначала то, что уронит выполнение: неверная граница цикла, необработанный
   пустой вход, переполнение, мутация коллекции во время итерации, опечатка в
   имени.
2. Потом сложность: назови текущую и целевую.
3. Стиль — в последнюю очередь. Почти никогда.

Не переписывай файл целиком. Не хвали. Не пересказывай код — пользователь его
видит.

# Достоверность

Если нужного куска нет во входе — он за пределами присланного текста — скажи это
одной строкой, а не догадывайся. Неверная подсказка хуже отсутствия подсказки:
пользователь начнёт править работающий код.
```

Уточнения с микрофона приходят отдельным ходом с маркером `<уточнение>` — «дай цифры», «короче». Оба промпта трактуют их как правку последнего ответа; соответствующий абзац дописывается на M6, когда канал микрофона появится.

## 12. Оверлей

Окно на `eframe`/`egui`. Против Tauri: единственный бинарь без зависимости от WebView2, меньше латентность отрисовки, полный контроль над окном.

`egui::ViewportBuilder`: `with_decorations(false)`, `with_transparent(true)`, `with_always_on_top()`, `with_taskbar(false)`, `with_mouse_passthrough(true)`, `with_active(false)`.

Вручную по HWND (`overlay/win.rs`):

1. `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)` — проверять BOOL и `GetLastError()`; при неудаче пробовать `WDA_MONITOR` и сообщить о деградации.
2. `SetWindowLongPtrW(GWL_EXSTYLE, ... | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW)` — окно никогда не забирает фокус (критично: приложение-конференция не должно видеть переключение окна) и не попадает в Alt-Tab.
3. `SetWindowPos(HWND_TOPMOST, ..., SWP_NOACTIVATE | SWP_NOMOVE | SWP_NOSIZE)`.

HWND берётся из `CreationContext` — он реализует `HasWindowHandle` (проверено на eframe 0.36.1); доступен и `cc.winit_window()`. Запасной путь: `EnumWindows` + фильтр по своему PID.

**Watchdog.** Display affinity привязан к HWND и теряется при его пересоздании. Раз в 3 секунды проверять `GetWindowDisplayAffinity` и восстанавливать. Расхождение — повод для явного предупреждения в UI, а не тихого исправления.

**Содержимое панели:**

```

─────────────────────────────────
а почему тут словарь, а не список…      ← распознанная реплика, приглушённо

▸ Строка 14: dict нужен для O(1)         ← ответ
  проверки, со списком будет O(n²).
· вход до 10⁵ элементов
· set хватит — значения не нужны
⌘ seen = set()
  if x in seen: return True
```

- Скролл — только хоткеями: окно click-through. `interactive` временно снимает `WS_EX_TRANSPARENT` для выделения текста мышью.
- Автоскрытие через `hide_after_s` (0 = не скрывать).
- `--metrics` добавляет строку с таймингами последнего цикла (§14).
- Режим выделения области (§13) — отдельный полноэкранный вьюпорт, тоже исключённый из захвата.

## 14. Латентность: бюджет и измерение

Требование Т2: цифры ниже — гипотеза, которую приложение обязано проверять на себе.

### Инструментирование

Метки: `t_speech_start`, `t_asr_first_partial`, `t_asr_commit[i]`, `t_spec_fire[i]`, `t_spec_ttft[i]`, `t_speech_end`, `t_final_fire`, `t_final_ttft`, `t_final_done`; для текста и экрана — `t_extract_start`, `t_extract_done` (с пометкой пути), `t_llm_ttft`. `--metrics` выводит их строкой в оверлее, `RUST_LOG=ghost::metrics=info` — в stderr.

Целевая метрика: **`t_spec_ttft[0] − t_speech_start`** — через сколько секунд после начала фразы появляется первый осмысленный черновик. Цель — **уложиться в 4 секунды**.

### Ожидания, голосовой путь

| Шаг | Локальный ASR (RTX 3080) | Облачный ASR |
|---|---|---|
| Захват + ресемпл + VAD | < 40 мс | < 40 мс |
| Стабильный текст отстаёт от речи | 1–2 с (цена LocalAgreement-2) | 0.3–0.8 с |
| Первый спекулятивный запрос уходит | ~3.5 с от начала речи | ~2.5 с |
| TTFT: LM Studio 7B на 3080 | 0.2–0.4 с | — |
| TTFT: Claude Opus 5, `effort: low` | 0.8–2 с | 0.8–2 с |
| **Черновик на экране (прод-связка)** | — | **≈3.5–4.5 с** |

Локальный ASR в целевые 4 секунды с облачной моделью скорее всего **не укладывается** — это и есть причина, по которой прод-ASR облачный, и ожидаемый результат замера, а не сюрприз. Обратное тоже верно: локальная LLM даёт TTFT втрое ниже прода, и замеры на ней завышают общую картину (§10.3).

### Ожидания, путь текста и экрана

| Шаг | Ожидание |
|---|---|
| CDP `Runtime.evaluate` | 20–80 мс |
| UIA обход дерева | 50–300 мс (дерево доступности Chrome медленное) |
| Захват области `xcap` + ресайз + PNG | 40–100 мс |
| TTFT с текстом на 300 строк | +0.3–0.8 с к базовому |
| **Разбор на экране после нажатия** | **≈1.5–3.5 с** |

**Порядок действий, если не укладываемся** (по одному шагу, с замером после каждого): облачный ASR → `fast mode` → порог спекуляции с 10 слов до 6 → `effort` вниз → `send_diff` вместо полного текста → более лёгкая модель для черновиков при Opus 5 на финале (ценой общего кэша: кэш привязан к модели).

## 17. Развитие: удалённый помощник (M7)

Второй человек подключается со своей машины, видит экран пользователя, слышит собеседника и шлёт текстовые сообщения, которые появляются в оверлее.

**Транспорт — два варианта:**

| | WebSocket + кадры | WebRTC |
|---|---|---|
| Реализация | `axum` 0.8 + `tokio-tungstenite`, JPEG 2–5 fps (`turbojpeg` 1.5) + Opus-чанки (`opus` 0.4) | `webrtc` 0.20 |
| Задержка | 300–600 мс | 100–200 мс |
| Объём кода | небольшой, состояний мало | существенно больше, ICE/DTLS/SDP |

Рекомендация: начать с WebSocket. Задача не про видео 60 fps, а про «увидеть код и услышать вопрос»; помощник читает медленнее, чем идёт поток.

**Сообщения помощника** приходят в оверлей отдельным блоком, визуально отличным от ответа модели: пользователь обязан всегда понимать, кто это сказал. Они же кладутся в историю с ролью `Helper`, чтобы модель их учитывала.

**Безопасность — часть функции, а не довесок.** Это канал, транслирующий наружу экран и звук разговора:

- выключен по умолчанию, включается явно и на время сессии;
- предварительно разделённый токен, TLS;
- **постоянный видимый индикатор в оверлее, пока канал открыт**, не сворачиваемый;
- отдельная аварийная клавиша разрыва.

## 19. Приватность и секреты

- `ANTHROPIC_API_KEY` и `GHOST_STT_KEY` — только из окружения. Никогда в конфиге, никогда в репозитории.
- По умолчанию на диск не пишется ничего: ни аудио, ни расшифровки, ни снимки, ни ответы. Дампы — явные флаги `--dump-audio`, `--dump-shots`, `--dump-text`.
- **При `backend = "local"` для обоих каналов ничего не покидает машину.** Это конфигурация по умолчанию и режим всей отладки.
- При `stt.backend = "cloud"` весь звук разговора непрерывно уходит стороннему провайдеру; при `llm.backend = "anthropic"` наружу уходят текст редактора и снимки. Оба факта отражаются индикаторами в статус-строке — пользователь всегда видит, что и куда уходит.
- Область захвата задаётся вручную именно поэтому: чем она у́же, тем меньше лишнего покидает машину.
- Логи в stderr, уровень через `RUST_LOG`. Содержимое реплик, кода и ответов в логи не попадает, кроме уровня `trace`.

## 21. Этапы

Порядок подчинён Т5: сначала весь цикл собирается офлайн на локальных моделях, внешние сервисы подключаются одним этапом в конце.

| Этап | Содержание | Критерий готовности |
|---|---|---|
| **M0** | Окно, исключение из захвата, watchdog, тест-матрица §20 | Прямоугольник виден глазами и отсутствует во всех записях матрицы, включая собственный снимок; фокус не уводится |
| **M1** | WASAPI loopback, ресемпл, кольцевой буфер, VAD, дамп в WAV | По клавише падает корректный 16 кГц моно WAV речи собеседника; VAD верно размечает границы реплик; смена устройства вывода переживается без перезапуска |
| **M2** | Локальный потоковый ASR (whisper + LocalAgreement-2), **бюджет VRAM** | Стабильный растущий текст; замерено отставание коммита от речи; whisper и модель LM Studio сосуществуют в VRAM 3080 без OOM |
| **M3** | **LM Studio**: трейт `Assistant`, стриминг, история, сброс, промпт `default`, спекуляции | Полный голосовой цикл работает **без единого внешнего запроса**; сняты метки §14 с явной пометкой, что TTFT локальной модели не характеризует прод (§10.3) |
| **M4** | **Канал текста:** CDP-каскад, UIA, снимки, номера строк, diff, профиль `livecoding` | Полный текст браузерного редактора попадает в контекст (включая непроскролленные строки — проверка на Monaco); разбор появляется за ≤3.5 с; голосовой вопрос учитывает актуальный код; статус показывает сработавший путь |
| **M5** | **Прод-бэкенды:** Anthropic, облачный ASR по протоколу §7.2, **перезамер латентности** | Замер проведён на прод-связке; вынесен вердикт по цели «черновик за 4 секунды»; префиксный кэш подтверждён по `cache_read_input_tokens` > 0 |
| **M6** | Микрофон: уточнения и `capture_self`; профили; конфиг и hot-reload; полировка UI; трей | Всё поведение управляется `config.toml` без пересборки |
| **M7** | Удалённый помощник (§17) | Помощник видит экран, слышит собеседника, его сообщения приходят в оверлей отдельным блоком; индикатор канала виден постоянно |

Два гейта: **M0** — осуществимость, **M5** — латентность. Оба способны закрыть проект, и M0 лучше пройти в первый день. M5 стоит в конце сознательно: до него всё проверяемо офлайн и бесплатно, а вердикт по прод-латентности всё равно можно вынести только на прод-связке.

## 22. Открытые вопросы

1. **Какая платформа для live coding.** От неё зависит, какая ветка JS-каскада §8.2 сработает: Monaco (CoderPad, CodeSignal, VS Code Web), CodeMirror (HackerRank и многие самописные), textarea. Знать заранее — значит не отлаживать вслепую на M4.
2. **Какая модель в LM Studio.** Для текстового пути годится любая; для снимков экрана нужна VLM. С учётом того, что whisper делит ту же VRAM (§10.1) — какая модель уже стоит и сколько занимает?
3. **`capture_self`** — распознавать ли собственные реплики в историю. Заметно повышает качество, удваивает расход на ASR. Решать после M6 по замеру разницы.
4. **Кто такой удалённый помощник** (§17) — доверенный человек на вашей же стороне? От этого зависит модель угроз: нужна ли только аутентификация или ещё и ограничение того, что он видит.
5. **Профили промптов** — нужны ли ещё, кроме `default` и `livecoding`?
6. **Основная клавиша.** `Right Ctrl` может конфликтовать с раскладкой; `Ctrl+Alt+1/2/3` конфликтуют с переключением вкладок в некоторых IDE и браузерах. Проверить на M1 и M4.
